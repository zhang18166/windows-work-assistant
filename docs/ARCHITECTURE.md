# 生命周期与维护

`Program` 先取得整合单实例和两份独立版的互斥名称；失败时提示退出独立版，不抢占或修改其他实例。
`SuiteContext` 拥有唯一 NotifyIcon、主窗体、输入法上下文、命名显示事件和 PDF EngineClient。
输入法上下文以宿主模式运行，隐藏其组件托盘；`SetModuleEnabled` 撤销异步切换、停键盘观察并隐藏浮窗，不覆写用户规则。
主界面是 WinForms 表格/停靠布局。输入法原设置作为子窗体嵌入页签，PDF 日志独立填满剩余空间。

`EngineClient` 先校验嵌入资源及缓存哈希，启动后加入 KILL_ON_JOB_CLOSE Job，再向匿名管道发开始命令。
不能通过命令拼接路径；配置通过 JSON 对象发送，并由转换核心校验、原子保存。
正常退出：禁止新操作、撤销输入法动作、发 quit、等待引擎清理；超过清理期限后只关闭自己拥有的 Job。
异常退出：Job 随宿主句柄关闭，清理其后代；转换子任务仍保留自己管理 Excel 的专用 Job。

引擎异常会在界面明确报告不可用，不让界面假装仍在监控；输入法模块可继续使用。当前不做自动无限重启，关闭整合版后重开恢复。
两份组件的用户数据路径保持兼容；测试通过环境变量隔离。生产启动不设置测试数据目录。

更新组件：把独立仓库提交的源码同步到对应 components 目录，更新 lock 的 commit/tree_sha256，构建和测试后发布新版本。
不要提交 bin/obj/dist/build/runs 等缓存或真实配置。生成 EXE 和 SHA256SUMS 通过 GitHub Release 分发。
